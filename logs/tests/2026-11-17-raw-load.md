# Test: Database creation and raw load of the four Zillow files

## What was tested
`sql/01_create_database.sql`, `sql/02_load_raw_files.sql` (procedure `raw.usp_load_wide_csv`) and the Task 4 checks in `sql/99_validation_checks.sql`, on the owner's PC (server `localhost`, SQL Server 2025).

## How
Data folder: the repo's own `data/` folder (`DataDir` = its full path on the PC).

1. `sqlcmd -S localhost -E -C -b -I -i sql/99_validation_checks.sql` before any SQL existed: failed as expected (`Database 'HousingMarket' does not exist`, exit 1).
2. `01`, then `02` with `-v DataDir=...`: the first `02` run failed with `Msg 511 Cannot create a row of size 8447` (321 `NVARCHAR(30)` month columns are too wide for one row). The procedure's error handler dropped the table, so no half-loaded table was left (checked: 0 tables in `raw`). Fix: month columns are `VARCHAR(30)`; the values are plain ASCII numbers. SQL Server still prints a warning that the *maximum possible* row size is over 8,060 bytes; real rows fit.
3. `02` again: loaded zhvi 895 rows / 321 months, zori 741 / 141, inventory 928 / 104, days to pending 716 / 104. Then `99`: all 12 checks PASS, exit 0.
4. Review Focus 2 (edge cases): a test file in the session scratchpad with a UTF-8 byte-order mark, Windows `\r\n` line endings, a quoted `"New York, NY"` and an empty last value was loaded into a throw-away table. The first column is `RegionID` (first character code 82 = `R`, no BOM), `New York, NY` is one value, the last value `2.25` has length 4 (no `\r`), and the empty last value is NULL. The throw-away table was then dropped.
5. Review Focus 1 (file the service can't read): loading a path that does not exist stops with `Msg 4860 ... does not exist or you don't have file access rights`, exit 1. The header read fails before any table is dropped, so a previous complete load stays as it was and nothing half-loaded appears. The real "Operating system error 5" did not happen: the SQL Server service account (`NT Service\MSSQLSERVER`) can read the repo folder on the owner's Desktop, so no copy to `C:\HousingData` was needed.
6. Review Focus 4: `02` then `99` run a second time: same row and column counts, all 12 checks PASS.

## Result
PASS

## Bugs
None. The row-size failure in step 2 was caught during development and fixed before commit.
