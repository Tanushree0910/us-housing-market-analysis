# Session journal

## Goal
Fix BUG-004: on Windows the hooks read Git Bash paths like `/c/Users/...` as `C:\c\Users\...`, so a commit in the main folder, raw-data deletes and `rm -rf` of the project could slip past them. Keep Linux behaviour unchanged.

## What changed
- `.claude/hooks/shellparse.py`: new `from_git_bash` helper (Windows only) that turns a leading `/<letter>/` or bare `/<letter>` into `<LETTER>:/`; `absolute()` calls it before resolving.
- `tests/test_git_guard.py`: new `GitBashPathTests` (helper, runs everywhere) and `GitBashGuardTests` (Windows only: main-folder commit denied, worktree commit allowed, `rm -rf` of project denied).
- `tests/test_hooks.py`: new `GuardGitBashTests` (Windows only: raw-data delete, redirect and edit via `/c/...` paths denied).
- `logs/bugs/BUG-004-hooks-misread-git-bash-drive-paths.md`: marked Fixed.
- `logs/tests/2026-11-24-hooks-gitbash-paths.md`: test log for the fix.
